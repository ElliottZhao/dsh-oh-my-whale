# 停在合并前

## 何时启用

用户说「弄到能合就行」「停在合并前」「别合，只弄就绪」。授予与 `ship.md` 相同的测试与推送权限，可以提交、推送、rebase、`--force-with-lease` 本任务分支，但不能合并。

## 做法

1. 按 `ship.md` 的 1 到 6 步：分支、改动、证明、复核、开 PR、盯。
2. 第一次推送前关掉自动合并，把 PR 移出合并队列；每次推送前再确认。阻止不了就报告再继续。
3. 最后一次修复后，行为变化与非平凡冲突解决重新证明。
4. 拉取基线分支，读实时 PR：头提交哈希、base、检查、评审、可合并状态。确认打开且不是草稿。
5. 套用合并门禁，给一个结论：
   - **就绪**：门禁通过，PR 留着打开。
   - **等审批**：只差一个必需的人类审批，确认是真阻塞。
   - **受阻**：说清什么挡着、试过什么、需要什么。
6. 报告 PR 链接、最终头提交哈希、结论、证明、复核结果与剩余风险。说明 PR 打开且未合并。

## 停止

- 得到一个结论并写完报告。
- 别人把这个 PR 合并了：报告这一情况。
- 六轮修复加盯仍无绿门禁：报受阻。

## 红线

- 绝不合并、开自动合并、进合并队列或推默认分支。
- 不让别的代理代做这些事。
- 结论要有证据：读到的检查清单与可合并状态。
