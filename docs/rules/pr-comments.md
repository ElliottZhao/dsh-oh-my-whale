# PR 评论

代理代用户写下的每条评论都要一眼可辨认、简短、可安全公开。

## 何时启用

要在 PR 评论、评审回复或关闭理由里发言时。

若评论属于某个流程，而该流程规定了自己的声明（例如分诊流程的声明），用流程的声明；本格式只用于流程未规定的评论。

## 做法

1. 写回复。结论先行。用支撑它的代码行、检查、测试或复现来引用。标明哪些是验证过的、哪些是判断。
2. 顶部放归属说明，正文在下面：

   ```md
   > [!NOTE]
   > **<模型> 代表 <用户> 回复**

   正文从这里开始。
   ```

   用宿主报告的模型名；没报就用宿主名。用用户的名字或 GitHub 登录名。
3. 扫完整评论，包括引用与附件，清掉秘密、令牌、私有路径与个人数据。
4. 预览最终 Markdown，确认说明与正文渲染成两个独立块。
5. 发布评论。
6. 确认 GitHub 返回了评论或评审 URL，打印它。
7. 只有回复发出后才解决评审线程。

## 停止

- 每条要发的评论都拿到了 URL。
- 连发两次失败。报错，不解决线程。

## 红线

- 归属说明用于：顶层评论、行内评审评论、回复机器人与他人、关闭理由。
- 不用于 PR 描述、提交信息或用户要求逐字发布的内容。
- 只用一处归属。不加签名、页脚、标题或分割线。
- 不写感谢、填充或「仍在处理」这类状态更新。
- 绝不猜模型名。
