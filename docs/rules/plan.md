# 计划

规格或票据已经是权威计划；本规则只覆盖没有规格、没有票据的小任务。

## 何时启用

任务跨多个文件或步骤，且没有规格、票据或既有计划可依。

## 做法

1. 一句话复述目标，列出要跑的命令。先读要改的文件再计划。
2. 写编号计划：每步一个动作，配一个命令或直接观察就能确认的验收。
3. 计划放临时工作稿（未跟踪文件或仓库外），不提交。
4. 冷读一遍：少了哪一步、哪个假设没核实、有没有更短路径。
5. 修订后只执行第一步，跑验收，读真实输出。没过就回到当前流程的验证步骤。
6. 在计划稿标完成，连同证据。
7. 计划被证伪就停下改剩余步骤。

## 停止

- 每一步完成且验收通过，端到端复核仍成立。
- 冷读两轮就执行；同一步连续两次失败，转 `unstick.md`。

## 红线

- 每步带一个可执行的验收。
- 一个改动只做一步。
- 计划控制在 3 到 10 步。
- 发布成规格或票据时只留决策，文件路径与代码片段留在临时稿。
