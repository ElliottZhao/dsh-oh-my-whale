# 并行切片

把宽而浅的工作切开交给多个并行执行者，再把它们证实的结果合并成一份报告。

## 何时启用

覆盖面优先的工作：审计、批量检查、多处排查、几个方案竞速、大范围探索。

## 做法

1. 先写清完成条件与最终报告要什么。
2. 选形状。把工作切成互不重叠的切片，或让 N 个执行者跑同一份任务书竞速，也可以两者并用。竞速就先定怎么选：第一个过、全排名、还是取最好。
3. 每个执行者一份能独立执行的任务书：目标、确切切片、怎么验证、要报什么。要让执行者测具体提交，就写确切 commit hash 与测量方法。
4. 会写文件的执行者各自给独立输出位置。
5. 一次全部发出。环境跑不了子代理，就按任务书在全新上下文里逐个跑。
6. 每个执行者报通过、有问题或受阻，并附证据：跑过的命令与输出。有问题时列出每个可证的问题，不只第一条。
7. 收结果。没有证据或跑错提交的结果退回重发一次。第二次仍不行记为缺口，不算通过。
8. 合并成一份报告：结论、每个切片或分支及其证据、缺口、按根因合并的重复项。

## 停止

- 每个切片都有结果或记为缺口，报告写成。
- 或竞速按第 2 步的规则产生胜者。
- 同一个执行者最多重发一次。

## 红线

- 执行者之间不共享可写状态。
- 缺的切片永远不算通过。
- 报告执行者证实的东西，不是它们声称的东西。
