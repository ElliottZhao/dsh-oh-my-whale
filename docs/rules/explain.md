# 解释代码

把「东西是什么、怎么跑、为什么长这样」讲成一段一个人能跟上的白话，让读者能放心地改它。

## 何时启用

用户问「这段代码怎么工作的」「为什么是这样」「给我讲讲这个」「带我一个子系统」。

## 做法

1. 弄清读者要什么。读对话：他们要改、要审、要调试，还是新手？挑三四个他们应该带走的东西。跳开他们已知的。
2. 量工作量。单函数一遍就够。跨多文件的子系统可以用两到四个并行只读子代理，各从一条角度，再合一遍。
3. 它怎么工作。读真实代码。从入口点追主运行路径到效果。记下谁持有哪块状态、边界在哪。引用文件与行号。
4. 为什么长这样。查提交历史、blame、PR 描述、关联 issue 与代码附近的评论。分开记录说什么与你推断什么，推断要标清。没有记录就说没有。
5. 写解释。先用一般术语给一句朴素定义，再接到本仓库。走一遍某人真用它的场景。然后是理由，再是边界情况。用小图或表帮一把。
6. 提出对一个命名部分更深入讲解。

## 停止

- 读者的问题被引用的代码与有来源的理由回答。
- 或者为找理由已经搜了三轮，没记录。说理由未知。

## 红线

- 不改代码。
- 每条关于行为的说法都指向文件与行。
- 绝不把对意图的猜测当事实。
- 解释想法，不列函数。
