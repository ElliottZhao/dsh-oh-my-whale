# 技能未覆盖的工程判断

以下条目不属于任何技能的规定，作为判断参考。技能已经覆盖的部分以技能为准。

## 结构

1. **先定数据形状。** 先选核心类型与结构，再写逻辑。
2. **边界处设防。** 在输入进入处校验：命令行、配置、网络、文件、外部接口。内部信任类型，核心逻辑保持纯。
3. **步骤幂等。** 重跑同一个步骤，包括崩溃后重跑，到达同一个状态。
4. **不要共享写者。** 并发参与者各自拥有文件、分支或键，再考虑锁。
5. **先迁移再删除。** 一次改动里搬走所有调用方并删掉旧接口，不留兼容层。
6. **按新需求重设计。** 把新需求当作第一天就存在来摆放。
7. **降低读者负担。** 内联只有一个调用者的包装，缩小可变作用域。
8. **摆出选项。** 没有先例的设计至少画两三个版本，宁可少而精。

## 测量与工具

9. **解释数字。** 找到限制测量的因素，确认它测的是该测的东西。适用于基准与评分。
10. **造工具。** 批量或重复的工作写成可重跑的脚本。

## 类型

- 让非法状态写不出来：用可辨识联合，不用一堆可选字段。
- 外部数据在边界解析一次，变成一个具名类型。
- 不可信输入用 `unknown`，不用 `any`；校验之前不做 `as` 断言。
- 类型从 schema 派生，不手写守卫。
- `default` 分支加 `never` 检查，新增变体让构建失败。
- 不能混用的原始值加品牌类型，比如用户 id 与订单 id。
