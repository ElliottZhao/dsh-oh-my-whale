# 写干净的中文

落笔就干净；写完扫一遍这些痕迹再改。保留意思与语气。

## 何时启用

写或改回复、文档、README、PR 描述、提交信息或注释时。流程规定了输出格式时，按流程格式。

## 该删的痕迹

用词
- 膨胀词与空转词：赋能、闭环、抓手、生态位、范式、底座、飞轮、无缝、极致、颠覆。换成具体动作或名词。
- 抽象名词堆叠：能力、体系、机制、维度、层面。能落到具体对象就落。
- 给弱动词垫脚的副词：显著提升、大幅优化。给数字或换更强的动词。

句子
- 「不只是 X，而是 Y」。直接说 Y。
- 硬凑三段式。用真实数量。
- 拖尾的「从而确保……」「体现出……」分句。删掉或换成实断言。
- 含糊来源：业内认为、很多人说。点名或删掉。
- 填充：为了能够、值得注意的是、由于……的原因、在一定程度上。
- 叠加模糊：可能会在一定程度上。留一个限定词或不留。
- 藏起施动者的被动句。说出谁做的。
- 只表达感受不解释机制。一句话放进任何项目的文档都成立，就删掉。
- 通用结尾：未来可期。以事实或下一步收尾。
- 翻译腔与长定语套叠。拆成短句，按中文语序重写。

格式
- 装饰性表情符号、弯引号、无意义的箭头与符号缩写。用中文标点与完整句子。
- 每个术语都加粗，以及「**标签：** 把标签再说一遍」这种条目。
- 破折号当中途连接。用句号或逗号。

对话习惯
- 开场与收尾：好问题、当然、希望这有帮助、有问题随时说。
- 反射式附和。给真实判断。

代码注释
- 复述下一行在干什么的注释、横幅注释、注释掉的代码。删。
- 只留解释代码表达不了的理由的注释。

## 改写流程

1. 想清读者是谁、读完要做或知道什么。
2. 删掉不服务这件事的每一句。
3. 同一件东西只用一个名字，用真实的文件、参数或命令名。
4. 一句里有两个意思就拆开。句长有变化。
5. 条件放指令前面。
6. 每个「它」「这」都指向一个明确的词。
7. 含糊的论断换成数字、命令或具体例子。
8. 再读一遍找痕迹。全合规但读起来僵的句子照样改。
