# 开 PR

PR 正文按 `pr` 技能的模板写。本规则补技能没有规定的生命周期动作。

## 何时启用

用户要求打开、提交或更新一个 PR。

## 做法

1. 先查这个分支是否已有 PR（`gh pr list --head <branch>`）。有就更新。
2. 对 PR 的基线分支做差异。单票据用默认分支；多票据集成流程用集成分支。
3. 读几条最近合并的 PR 标题，沿用格式。标题说清对用户变了什么、为什么重要。
4. 正文调用 `pr` 技能。界面改动的证据优先截图，执行类证据用测试输出。
5. 草稿策略按流程：单票据可直接以可评审状态创建；多票据集成流程先开草稿，全部完成后转就绪。
6. 扫标题、正文与附件，清掉秘密、令牌、私有路径与个人数据。
7. 打印 GitHub 返回的 PR URL。

## 停止

- GitHub 返回了 PR URL。要盯就转 `watch-pr.md`。
- `gh pr create` 连续失败两次：GraphQL 限流就用 REST 重试一次；再失败就报错。

## 红线

- 用浅文件树或布局差异表达文件职责，代替逐文件清单。
- 正文保持简洁，不加署名行、前言或页脚。评论归属走 `pr-comments.md`。
