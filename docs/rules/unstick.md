# 从重复失败里脱身

硬缺陷的成因诊断交给 `diagnosing-bugs`。本规则只处理普通任务里同一修复反复失败。

## 何时启用

同一个修复或同一类修复在普通任务里连续失败两次，且没有走缺陷诊断流程。

## 做法

1. 停手，换思路。
2. 每次失败写一行：改了什么、结果如何、错误文本。
3. 写出这些尝试共享的假设，一句话。
4. 用最便宜的探针直接验证假设，答案要是或否。贴结果。
5. 假设为假，就找到了真问题，从新事实规划修复。
6. 假设为真，列三个不同做法。不同指换机制、换库、换层或换数据路径。每个写一行代价与风险。
7. 选一个，用一句话说明为什么。
8. 失败尝试留下残局就从干净状态重来：`git stash` 或 `git checkout -- <files>` 回滚，只应用选中的做法。
9. 把错误假设或选中的做法记进决策账本。
10. 回到当前流程的验证步骤。

## 停止

- 探针解释了失败，或新做法通过检查。
- 走满两次仍失败：停下向用户报告尝试、验证过的假设与证据，请用户指方向。

## 红线

- 每次尝试换机制或数据路径。
- 证据胜过推理。
- 保留失败清单，它是报告里最有用的部分。
- 新做法前回到干净状态。
