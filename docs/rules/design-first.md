# 模块落地

接口形状已经由流程定下时，先让形状可编译，再填实现。接口探索用 `codebase-design`（模型可调用）；本规则只补落地动作。

## 何时启用

模块接口、类型或模块边界已经定下，要开始写实现。

## 做法

1. 把选中的形状写成真实文件：类型、签名、模块边界，加抛「未实现」的桩。
2. 跑类型检查或编译，贴输出。桩必须通过。
3. 一次填一个桩，每填完跑类型检查与相关测试。
4. 形状错了就停下改形状，不只在函数体里补。
5. 完成后删掉残桩与未用类型，搜索「未实现」确认没剩。

## 停止

- 所有桩实现，类型检查与测试通过并贴输出。
- 形状在实现中被改了三轮：回到流程重新对齐。

## 红线

- 形状只通过流程的设计对比改动。
- 证据是编译器与测试输出。
