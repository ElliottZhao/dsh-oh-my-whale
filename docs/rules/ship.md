# 交付到合并

## 何时启用

用户明确要求「发出去」「一路做完」「绿了就合」时。请求授予三件事：为证明跑测试与检查不必先问；对本次任务自己的分支用 `--force-with-lease`；门禁通过后合并。别的都不授予。

## 做法

1. 在默认分支上就先建新分支。多票据集成工作按流程在集成分支上走。
2. 做满足目标的最小改动。只修被报告的那个场景。
3. 证明 diff 的每一部分：复现、修复、再跑同一复现；跑持续集成检查；界面或运行行为跑起来看。把命令与输出记进笔记。
4. 复核改动，复核改过的地方重新证明。复核用 `code-review` 技能。
5. 变基到 PR 的基线分支（单票据默认分支；集成流程用集成分支），按 `pr.md` 开 PR。加一行说怎么证明的。
6. 按 `watch-pr.md` 盯 PR，修真实发现与持续集成失败，逐个证明，推送，再盯。
7. 在最新提交上核对合并门禁，用仓库惯用方法合并。不用 `--admin` 或绕过。

合并门禁在最新 head 全为真：证明覆盖完整 diff；必需检查全绿；评审机器人结束；每条发现已修或带理由答复；没有人类评审要求改动；分支最新且可合并。

## 停止

- PR 合并且报告写完。
- 证明不了或门禁过不去且修不了：问用户。
- 下一步要删数据、碰生产、关 PR 或推别的分支：问用户。
- 六轮修复加盯仍无绿门禁：停下报告阻塞。

## 红线

- 检查还挂着时不结束回合，用看护等。
- 证据是本会话看过的输出，没有输出的说法不算证明。
- 范围锁死。评审带来的额外工作列为后续。
- 集成流程里，把各票据合进集成分支是流程内的合并动作，不属于门禁意义上的合并；最终 PR 的合并仍以本规则授权为准。
