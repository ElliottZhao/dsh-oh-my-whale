# 长任务的状态账本

长任务会忘掉自己为什么开跑。账本让目标留在视野里，也让之后的人能信任结果。上下文交接用 `handoff`；本规则只记长任务内的决策。

## 何时启用

多阶段、自主运行、或之后要给人评审的工作；或用户要求记录决策时。

## 做法

1. 建一个 TSV 账本文件（例如 `.ledger.tsv`），放未跟踪的临时目录，默认不提交。表头 `时间	阶段	决策	原因	证据	结果`。第一行写目标与完成条件。
2. 每步之前重读目标行与最近十行，核对下一步是否仍在为目标服务。不在就记下漂移并纠正路线。
3. 每次真实决策后追加一行：
   - `时间`：ISO 8601 时间。
   - `阶段`：阶段或工作流。
   - `决策`：你选了或做了什么，一行。
   - `原因`：用白话说的理由。
   - `证据`：指针，不写散文。一次提交哈希、`file:line`、一个命令与结果、或一个产物路径。
   - `结果`：结果，比如「测试通过」「已回滚」「未闭合」。
4. 每个单元格一行，不含制表符。
5. 回滚和放弃的工作也要记，带理由。失败是最有用的行。
6. 结尾加一行汇总，把文件指给用户。评审需要才提交。

## 停止

- 运行结束，汇总行已写。
- 连续三行对目标没有进展，停跑并报告。

## 红线

- 每行都要有能打开或重跑的证据。「看起来没事」不是证据。
- 行要像跟同事交代那样写，平实、具体。
- 不改写旧行。追加更正。
- 决策定稿后写进票据或提交，账本不成为并行的第二事实源。
