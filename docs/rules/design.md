# 界面实现（方向已定）

只用于**视觉方向已定**时把界面做出来。要回答「该长什么样」、方向还没定，先用 `prototype` 技能（原型阶段不适用本规则的状态、无障碍与截图验收）。

## 何时启用

界面方案已定，要把正式页面做出来，或重排一套已定方向的界面。

## 做法

1. 读任务书与项目，找主题、受众、用户要做的那个动作、技术栈、已有品牌。方向含糊先问，不按模板猜。
2. 先定方向说明：目的、受众、语气、一件让人记得的东西、模式（说服/操作/阅读）。从主题自己的世界取，不从类别的常见长相取。
3. 先定令牌再写组件：
   - 字体：一套明显不同的展示字体与正文字体。展示不用默认字体。字号 5–7 级，正文 16px 以上，行长 80 字以内。
   - 颜色：4–6 个具名十六进制值。一个主色铺大面积，一个锐利强调色只用在动作上。
   - 间距：4px 或 8px 基数，一两个圆角值，一种阴影或不用。
4. 带着意图排版。选密度：说服用疏，工具用密。用真实文案与可信数据，不用占位。
5. 把正式界面的状态做全：悬停、键盘焦点、禁用、空、加载、错误、长内容。对比度 4.5:1、聚焦环可见、字段有标签、触控目标 44px、图片有 alt、尊重减少动效。
6. 在 1440px 与 390px 宽各截几张图，对着方向说明与常用反例检查，一批修完再截。
7. 删掉一件不干活的装饰。

## 停止

- 方向说明与令牌存在，代码用了令牌。
- 两种宽度的截图没有水平滚动，常用反例没有出现，状态做全、无障碍底线达到。

## 红线

- 任务书指定了字体、颜色或风格就用它，即使它在禁用列表。
- 精修保留界面的身份，重设计保留内容与功能。
- 本规则不用于原型阶段；原型阶段按可交互原型流程做，不做状态、无障碍与截图验收。
