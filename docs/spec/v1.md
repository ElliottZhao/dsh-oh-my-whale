# v1 规格：闭合回路的一对一个人 Agent

## Problem Statement

我现在用的 agent 每次开新会话都从零开始。它不记得我上次说过的偏好，不知道哪些决定已经做过了，也不会因为熟悉我而改变说话方式。我得反复交代背景。我说过"以后别这样"，它也不会真的改掉。我的理解、判断和经验散落在一次次会话里，会话一关就没了。

## Solution

一个本机常驻的记忆与理解内核，加一个跑在宿主里的薄适配层。它把每次会话里值得留下的东西抽成带时间与证据的条目，把对我的理解沉淀成可编辑、可审计的画像，把对自己的认识沉淀成一组规则。每轮对话前，它决定这一轮该注入什么记忆，并保证注入可解释、可关闭、不拖慢主流程。数据全部留在本机，一个文件，能导出、能删除、能回滚。

## User Stories

1. 作为用户，我希望新会话里它能准确提起我三天前说过的一件事，并指出那次是在哪一轮说的，这样我不必重复交代背景。
2. 作为用户，我希望它记得我的偏好，并在我说"以后别这样"之后立刻改掉，这样我不用反复纠正同一个问题。
3. 作为用户，我希望被改掉的旧偏好仍留有记录与失效时间，这样我能查到它曾经怎么理解我。
4. 作为用户，我希望两个人对不上时它明确告诉我"这两条冲突了"，这样我知道它在纠结什么，不必猜。
5. 作为用户，我希望它记得的每条东西都附着我当时说的话，这样我能判断它是不是记错了。
6. 作为用户，我希望它在没有任何相关记忆时明说"没有相关记忆"，这样我能分清是它没记住，还是记住了却没用上。
7. 作为用户，我希望它能在这一轮告诉我它为什么这么做，答案能指到具体的条目或规则，这样我能审计它的判断。
8. 作为用户，我希望记忆注入超时或内核没起来时对话照常进行，只是暂时没有记忆，这样它不会因为记忆而卡住。
9. 作为用户，我希望内核完全没配模型时它仍然记得原始观察，只是不做理解，这样降级不会静默发生。
10. 作为用户，我希望它能被我自己编辑，而不只有它能改我的画像，这样我能纠正它记错的地方。
11. 作为用户，我希望画像里每个块有上限，不会被一条条事实塞爆，这样它理解我的那部分始终读得下去。
12. 作为用户，我希望它对自己的认识是一组可增删改的规则，这样错误的认识能被淘汰，不会随时间变成一段越来越长的自我总结。
13. 作为用户，我希望它把有争议的自我认识标出来，这样我能看到它的矛盾，而它不会悄悄删掉。
14. 作为用户，我希望它在空闲时整理记忆：合并重复、让过时的事实失效、把成功的做法提炼成规则，这样每次对话都不必做这些昂贵的判断。
15. 作为用户，我希望删除操作先变成提案、由我确认后才真删，这样它不会自己抹掉重要的东西。
16. 作为用户，我希望它记得我们之间的状态，比如哪些话题是禁区，这样它不会反复踩到。
17. 作为用户，我希望它在会改变外部世界的动作前先问我，并且我拒绝的理由会被记住，这样它下次不会犯同一个错。
18. 作为用户，我希望它只连我自己配置的模型服务，不把数据发到别处，这样我知道什么东西出了这台机器。
19. 作为用户，我希望每次调用外部模型都把用途、服务商与模型记进账本，这样我能查清一笔花费从哪来。
20. 作为用户，我希望全部数据在一个本地文件里，能导出、能删除、能回滚到上一个版本，这样我不被绑架。
21. 作为用户，我希望第一次使用时它问我几个定向问题，这样冷启动不必从一张长表开始。
22. 作为用户，我希望没有历史时的对话也不受影响，只是暂时没有画像可注入。
23. 作为用户，我希望它整理记忆的过程不打扰我，只在有提案时通知我一次。
24. 作为用户，我希望同一件事不要每轮都注入一遍相同的记忆，这样上下文不会被重复内容占满。
25. 作为用户，我希望注入的记忆有明确上限，这样某次召回不会把整轮对话挤出窗口。
26. 作为用户，我希望它记得的是带时间的状态，能回答"当时我偏好什么"，而不只给最新值。
27. 作为开发者，我希望记忆条目的结构与来源在代码里可读可导，能按需要导出成文本。
28. 作为开发者，我希望领域结构只定义一处，两端类型从它生成，这样两侧不会各改各的。
29. 作为开发者，我希望每轮注入的行为有一组可判定的回归测试，这样改动不会悄悄破坏注入纪律。
30. 作为开发者，我希望每条验收都有对应测试，跑完在十分钟以内，这样"完整"不是一句形容词。

## Implementation Decisions

**架构。** 宿主内薄适配层（TypeScript，跑在宿主进程里）加本机常驻内核（Rust）。两者只经 loopback 通信，内核不监听外网。内核持有长期状态与检索，适配层只管接宿主接缝。见 ADR-0001。

**没有中央仲裁者。** 系统里只有一个地方决定"这一轮注入什么"，就是 Composer。预算退化为按能力角色的配置常量，主动介入不在 v1。见 ADR-0004。

**不归档原文。** 内核不保存原始会话文本，记忆条目的证据内嵌。宿主自己的会话日志已经是可回放的完整记录，再存一份属于重复归档。推论有两条：条目证据必须自足，指针会悬空；抽取器改进不回溯历史。见 ADR-0005。

**计划不单独存储。** 计划属于会话内容，随宿主日志走。见 ADR-0005。

**内核自持凭据。** 内核维护自己的配置文件与密钥，不读宿主配置。见 ADR-0003。

**配置按能力划分。** 能力族是 LLM、Embedding、CrossEncoder、Decision。角色（抽取、查询改写、排序、弃权判定）各自绑定一个 provider 的一条能力，可带有序 fallback 链。出站白名单等于已配置 provider 的集合。

**数据模型。** 观察、记忆条目（事实与情节两级，带有效区间与内嵌证据）、画像块（有 token 上限，原地更新需精确匹配旧值）、自我块、规则、关系状态、视图、账本条目。不引入图数据库。

**注入。** 稳定身份走系统提示的具名段，记忆与外部内容走用户角色的运行时上下文，靠内容摘要去重。注入只在请求派生之前发生。适配层处理器绝不抛错，召回异常吞掉并记降级，因为处理器抛错会结束整个回合。空召回显式写"无相关记忆"。

**降级链。** 未配向量能力时用全文检索；未配排序能力时用规则排序；完全没配语言模型时进入"记录但不理解"模式，账本记一次降级。

**召回预算。** p95 不超过 800 毫秒，超时按无记忆模式继续。每轮最多 8 条、1200 token。

**里程碑与依赖。** 内核骨架，然后摄入与记忆，然后召回与注入（首条端到端链），然后用户模型与自我，最后关系、守卫、评估、入职。每个里程碑自带验收。

**v1 完整但不并铺。** 十一个模块都要做到成品并带评估，按依赖链依次交付。

## Testing Decisions

**接缝一：内核的进程间契约。** 这是最高、也是最少的接缝。检索、写入、组装、账本、配置全部经它被测试，不穿透到 Rust 内部。测外部行为：给一段观察，问一次召回，看返回的条目与解释。

**接缝二：真实无头运行。** 不给适配层造假宿主。测试脚本新建一个一次性 profile，装入被测 bundle，用 `dsh --profile headless --json "<任务>"` 跑一轮，然后断言两件事：模型实际收到的注入内容（从会话日志读 `user/message` 与 `system/message`），以及适配层的行为（该注入时注入、该沉默时沉默、超时后不阻塞、空召回写对文本、内容不变不重复注入）。宿主自带无头模式、stdin 输入、`--session-id` 续跑与 `--json` 结构化事件，这套断言因此可以是纯脚本。测试用独立 profile，不碰日常使用的那个。

**什么算好测试。** 只测外部可观察的行为，不测实现细节。每条测试的失败信息要说清是哪个行为坏了。同一场景重复 k 次全过才算通过（Pass^k），单次成功不认。

**先写测试。** 每个模块先有会红的验收用例，再写实现。后补的测试会退化成照着实现写断言。

**数据。** 跨会话召回用 LongMemEval 的 MIT 子集，中文场景另建一个小集。整理与淘汰用合成历史加噪声注入。

## Out of Scope

远端托管、账号与多用户；中央仲裁层与投机执行；计划的独立存储；原始会话归档；图数据库与图遍历；本地兜底模型自动下载；人格面具式的表达改造；形式化推理与世界模型核心建模；跨设备同步（只做文件导出与导入）。

## Further Notes

- 未决：宿主注入钩子是否自带超时。若没有，超时由适配层用取消信号自己实现。
- 未决：系统提示的更新路由只有"在前导位置"一种，它对每步装配的影响需要确认。
- 风险：LongMemEval 以英文合成历史为主，中文召回的实际效果需要自建小集验证。
- 风险：Rust 与 TypeScript 的类型生成方案一旦定下就难改，动手前需要一次试探性验证。
