# 没有中央仲裁者：注入什么只由 Composer 决定

我们曾设一个 `Governor` 编排模块，负责「这一轮做什么、交给谁、给多少预算、注入哪些上下文」，后来删除。

理由：单用户、单 agent、每轮只注入一次的系统里，宿主每轮已经把系统提示与本会话历史一起提交给模型（历史有界，超限走压缩）；剩下的唯一决定是**这一轮注入什么**，而这个决定只有一个合理归属——Composer。多一个仲裁层，只会让「该不该召回」分属两个模块各猜一半。

代价如实记账：**预算不再随情境自适应**，退化为按能力角色的配置常量；**主动介入没有时机门槛**，退化为宿主定时任务加一句提示词，容易变成打扰，因此 v1 不做主动性。

## Consequences

- 任何「要不要注入 / 注入多少」的判断，写进 Composer，不新开模块。
- 若将来重新需要按情境调预算，应作为 Composer 内部策略出现，而不是恢复一个独立编排层。
